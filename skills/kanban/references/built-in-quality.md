# Built-In Quality, Reusable Assurance, and Improvement

Read this reference when defining or changing principles, tenets, reusable
assurance, task guidance, quality signals, process experiments, or the current
flow constraint.

## Governing chain

Keep these meanings distinct:

- A **principle** is a durable, sourced, outcome-oriented governing belief.
- A **tenet** is actionable standard work derived from one or more principles.
- A **guidance snapshot** pins the exact effective tenet versions for one task.
- An **obligation** is the task-specific action, constraint, check, safeguard, or
  risk disposition produced from an applicable tenet or assurance finding.
- **Evidence** proves an obligation against an exact artifact revision.

Preserve the chain:

`source -> principle version -> tenet version -> frozen guidance -> obligation -> evidence -> outcome`

Assurance is complete only when every material finding is incorporated as an
obligation, explicitly rejected by the proper authority, or given an
attributable not-applicable disposition. A consultation alone is not assurance.

## Precedence and freezing

Resolve guidance from suite defaults, project additions or overrides, narrower
intent/product-area policies, and finally authorized task exceptions. A narrow
override records what it changes, rationale, authority, scope, expiry, source or
decision, and rollback condition. Never erase the superseded version.

Freeze the effective guidance with the task work profile and review plan. A
profile change stales both. Deliver workers only relevant tenets and obligations
for their stage, artifacts, risks, and specialist context; keep the complete set
in SQLite so context filtering cannot silently omit a required disposition.

## Production and control

Before Active, required tenets must be materialized, validly inherited,
attributably not applicable, or covered by an authorized exception. Prefer the
earliest deterministic feedback mechanism: contract, type, schema, test, static
check, policy-as-code rule, architecture fitness function, rendered
configuration check, deployment safeguard, operational probe, or rollback test.

Control review independently checks the pinned guidance, dispositions,
obligations, artifact, and evidence. A task cannot complete with planned or
blocked obligations or unresolved stop-quality signals.

Reusable assurance baselines name their scope, assumptions, premise and
guidance hashes, evidence, freshness, invalidation conditions, and approver.
Inheritance is permitted only while every premise remains true.

## Jidoka

When a material abnormality appears, contain it and stop only the affected work
or value stream. Record occurrence cause, escape cause, systemic cause,
countermeasure, owner, and recurrence test. Repairing the artifact is not the
same as improving the process that produced or failed to contain the defect.

## Theory of Constraints

Record the system goal, candidate or active constraint, evidence, buffer target
and state, and exploit/subordinate/elevate actions. Dispatch to improve
end-to-end throughput and customer outcomes. Do not maximize agent or specialist
utilization, and do not feed additional implementation inventory into an
overloaded review constraint.

## Kaizen experiments

Experiment on a visible baseline tenet. Pin baseline and variant versions,
hypothesis, assignment scope, exclusions, safety boundaries, measures,
observation window, owner, outcome, unintended effects, decision, and rollback.
Safety, human-authority, legal, destructive-action, and other high-impact
controls cannot be weakened as an ordinary autonomous experiment. Promotion
creates a new tenet version after research, evaluation, independent review, and
an authorized decision; it never rewrites historical assignments.
